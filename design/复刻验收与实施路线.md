# 复刻验收与实施路线

## 1. 完成标准

每项来源功能分配稳定ID，以文档主题/源码目录/API来源行/测试文件定位。状态依次为：已收录 → 已审计 → 已设计 → 已实现 → 行为通过 → 视觉通过 → 包消费通过。当前交付主要处于“已收录和设计草案”，不是已实现。

每个API记录：来源名称/版本标记/弃用、所属子组件、类型、必填、默认值、空值、React名称/类型、实现位置、单元/浏览器/截图用例、已知差异和状态。初始数据保存在api-matrix.json，包含源表的全部列；复杂类型不能靠camelCase转换宣称完成。

## 2. 对照环境

建立两个隔离宿主：固定来源工作树的Vue参考页、React19候选页。同一浏览器版本、操作系统、字体、DPR、viewport、缩放、locale、时区、主题、数据和动画设置。组件状态由统一场景描述驱动；不在一棵DOM树混用两份全局样式。

截图比较采用区域截图、差异图和数值指标；默认不允许未解释差异。字体抗锯齿等环境噪声只对明确区域设最小容差，禁止全局大阈值掩盖布局错误。尺寸、位置、滚动范围、可点击区域另做几何断言。过渡既测试静止终态，也测试开始/完成事件与快速反向操作，不通过关闭动画逃避动画等价。

## 3. 行为矩阵

| 维度 | 必测项 |
|---|---|
| Props | 缺省/显式值、0/false/空串/null、非法边界、动态更新、嵌套配置覆盖 |
| 状态所有权 | 受控/非受控、父级拒绝回写、默认值只初始化、reset |
| 事件 | 参数类型、顺序、次数、取消、原生事件与值事件区别 |
| 插槽 | 静态节点、0/空串、条件渲染、作用域参数、fallback、优先级 |
| 实例 | focus/blur/scroll/validate等源方法、返回值、Promise、卸载调用 |
| 输入 | 键盘、鼠标、触摸、IME、粘贴、光标、选择区和格式化 |
| 异步 | debounce、请求交错、取消、失败重试、卸载和StrictMode |
| 浮层 | Portal容器、嵌套、点击外部、Escape、遮罩拖动、层级、滚动锁、恢复焦点 |
| 表单 | 初始值、动态字段、路径、规则变化、校验并发、错误清除、disabled/size继承 |
| 日期 | 月末/闰年/跨年/周起始日/禁用边界、范围顺序、日期格式及DST |
| 大数据 | 稳定key、动态尺寸、过滤后滚动、节点卸载和焦点、缓存失效 |
| 文件/图片 | 成功、失败、取消、限制、跨域配置、自定义请求、预览与移除 |
| SSR | 导入安全、服务端输出、hydration无错、首屏一致、Portal延迟挂载 |
| 样式 | 所有尺寸/语义色/状态、浅深主题、namespace、长内容、窄容器、缩放 |
| 可访问性 | 名称、角色、状态、键盘顺序、Tab循环、读屏关联和焦点可见性 |
| 资源释放 | timer/raf/listener/observer/请求/锁计数/DOM挂载点无泄漏 |

每组件按适用性选择，标N/A须写理由，不能只复用通用模板。源文档的功能标题和示例全部要有对应场景。来源测试静态标题索引只是入口，必须读取断言和动态生成测试。

## 4. 建议工具与验证产物

单元行为建议Vitest + React Testing Library + user-event；浏览器和截图建议Playwright；无障碍自动检查可用axe并补键盘人工检查；SSR用react-dom/server与hydration场景；类型通过独立消费项目和tsc验证。这是设计建议，本次未安装或运行这些工具。

验收产物至少包含：来源/候选截图、差异图、交互事件轨迹、测试报告、API映射、类型消费用例、差异台账和来源版本。不能只写“测试通过”而没有对应场景或证据。

## 5. 按依赖实施，不删减范围

| 阶段 | 内容 | 出口 |
|---|---|---|
| 0 基线审计 | 校准API矩阵、源码/测试/文档差异、完整React签名、图标/样式许可证 | 未裁决项有明确阻塞记录 |
| 1 基础设施 | namespace、theme、locale、受控Hook、Context、collection、ref、SSR、服务宿主 | 基础生命周期和隔离用例通过 |
| 2 基础展示和布局 | Button/Icon/Link/Text/Tag/Badge/Avatar、布局容器、Card/Divider/Empty/Result/Skeleton等 | 第一批Vue/React视觉对照闭环 |
| 3 输入和表单 | Input/InputNumber/InputTag/InputOtp、Checkbox/Radio/Switch/Rate/Slider、Form | 值/事件/校验/IME模型稳定 |
| 4 浮层和反馈 | Popper/Tooltip/Popover/Popconfirm、Dialog/Drawer、Loading/Message/Notification/MessageBox | 焦点、Portal、嵌套、锁和服务上下文通过 |
| 5 选择与导航 | Select/Autocomplete/Mention/Cascader、Menu/Tabs/Pagination/Anchor/Steps等 | 键盘游走和远程竞态通过 |
| 6 日期与颜色 | 日期时间内核、各面板/选择器、Calendar、ColorPicker | 格式/locale/范围/边界通过 |
| 7 数据与性能 | Tree/TreeSelect/Transfer/Table、VirtualList/TreeV2/SelectV2/TableV2 | 大数据与复杂实例能力通过 |
| 8 媒体与其他 | Upload/Image/ImageViewer、Carousel/Scrollbar/Watermark/Tour等及索引剩余组件 | 所有目录和文档主题都有验收结论 |
| 9 发布验证 | 包体/按需、ESM/CJS、类型、CSS/SCSS、SSR和真实应用 | 完整消费矩阵通过 |

阶段是依赖顺序，可在基础设施稳定后安排独立实现；不能将后期组件当作范围外。每个阶段开始前以组件索引为总账检查遗漏。

## 6. 不把扩展功能混入复刻

TableV2与Table、TreeV2与Tree、SelectV2与Select分别依据来源验收，虚拟版本不必具有来源普通版的全部功能。React额外的非受控入口、RSC边界和Hook适配要单列“框架适配”；业务新增和来源缺陷修复单列“扩展/修复”，不能使复刻基线失去可比性。

## 7. 本次验证范围

本次只核对文档和目录覆盖、文件生成、JSON可解析、链接目标和示例引用；未实现组件，未执行React单元/浏览器/SSR/视觉/类型消费测试。coverage.json中的false是尚未进行，不表示测试失败。设计内容仍需逐组件审计。
